HAOKE PLATFORM / API 0.2

统一账号，独立游戏。

这是本地可用的接口参考，不依赖外部 CDN。网站承载账号与管理；房间、准备与表情接口供游戏客户端调用。

目前能做什么

邮箱验证码登录、游戏资料、六人房间与固定表情、网站及 AI 管理接口已经实现。Liquid Wars Android 1.84已接入原生邮箱登录、匹配和公网中继。匹配等待8秒后空位补电脑，最低1名真人、总计6队。开始前所有真人必须登记兼容客户端。其他游戏需独立适配；客户端唤起及可信战绩尚未实现。

登录与权限

  • 网页：HttpOnly hk_session Cookie；登录后的写请求带 X-CSRF-Token，从 GET /api/me 获取。
  • 原生玩家：验证码验证时传 client: "native"，保存返回的 Bearer 会话；有效期七天。
  • 外部 AI：独立 hkai_ 凭证，放在受信任服务端。admin:read 仅查询，admin:full 可修改网站业务。不能用管理凭证冒充玩家。
  • 本地管理员：默认 owner@haoke.local，验证码从登录页本地开发收件箱读取。生产环境必须配置真实邮箱与 SMTP。

写入、重试与错误

  • 管理写请求还须 Idempotency-Key：8–128 字符。同一操作重试复用，同键不同内容返回409；保存七天。
  • 创建与轮换密钥只展示秘密一次，重试响应不会重新返回秘密。
  • 统一错误格式：{"error":{"code":"…","message":"…"}}。401重新登录，403权限或CSRF，409状态冲突，410房间失效，422字段错误，429频率限制，503服务不可用。
  • 业务修改与调用结果分别记录；日志不保存验证码、Authorization、Cookie或请求正文。

可运行的只读示例

在终端环境变量 HAOKE_ADMIN_TOKEN 中配置你的授权凭证，再执行项目中的示例。管理写入示例见 docs/API.md。

python scripts/admin_api_example.py
python scripts/admin_api_example.py --base-url http://127.0.0.1:8768

实时连接

玩家先调用 POST /api/realtime-ticket 获取30秒有效、一次性的 ticket，再连接 /ws?ticket=…。每20秒发送 {"type":"ping"}，监听 connected / room / emote / pong。表情通过 HTTP 接口发送，服务端只接受官方ID，间隔至少3秒。网站邀请页只读取房间概况，不占席位。

原生游戏接入

Bearer登录后调用 POST /api/online/enter，协议30、build至少53。匹配使用 /api/matchmaking/enqueue|status|cancel；房间开始后获取 /api/online/rooms/{code}/ticket，连接 /ws/game?ticket=…。此连接承载原生二进制流。SDK请设置真实产品User-Agent，例如 Haoke-Admin-SDK/0.3。房主离开结束战斗；电脑不会增加注册或真人在线统计。
